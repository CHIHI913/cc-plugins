# ユーザータイプ ガイド

## このガイドについて

ターゲットセグメント内の行動パターンを類型化する方法を解説する。

- テンプレート: [template.md](template.md)
- 見本: [example.md](example.md)

## ユーザータイプとは

STPで選定したターゲットセグメントの中で、行動パターンやニーズ構造の違いによってユーザーを分類するフレームワーク。

- **セグメント**: 市場全体を分ける（STPで実施済み）
- **ユーザータイプ**: ターゲット内の行動パターンを類型化（ここ）
- **ペルソナ**: 各タイプの中の具体的な1人の人物像

**目的**: ターゲット内の多様性を可視化し、タイプごとに最適なソリューションを設計する
**インプット**: インタビュー結果、VPC
**アウトプット**: ユーザータイプマップ + タイプ別ソリューション仮説

## ディスカバリーワークフローにおける位置づけ

```
STP（ターゲット選定）
    ↓
VPC → 仮説 → インタビュー → 分析
    ↓
【ユーザータイプ】◀ ここ（インタビュー結果から発見）
    ↓
ブランドコンセプト
```

> ユーザータイプは最初から設計するものではなく、インタビューや分析の過程で**発見**されるもの。

## 作り方

### 1. 軸を定義する

インタビュー結果から、ユーザーの行動を分ける**2つの軸**を見つける。

軸の候補：
- 課題感の強さ（軽い ←→ 重い）
- ニーズの顕在度（潜在 ←→ 顕在）
- 行動の主体性（受動的 ←→ 能動的）
- 情報リテラシー（低い ←→ 高い）

### 2. 4象限にタイプを配置する

2軸の交差で4象限を作り、インタビュイーがどこに位置するかをプロットする。共通するパターンが見えたら、タイプとして命名する。

### 3. 遷移パスを設計する

タイプ間の遷移（どのタイプからどのタイプに移るか）とそのトリガーを定義する。プロダクトがこの遷移をどう支援するかがソリューション設計の鍵。

### 4. タイプ別ソリューション仮説を立てる

各タイプに最適なソリューションは異なる。短期ターゲット（最も優先度の高いタイプ）のソリューションから設計し、長期ターゲットは段階的に対応する。

## 注意点

- **最初から4象限を設計しない**: インタビューデータから帰納的に発見する
- **タイプ名は直感的に**: チームで共通認識が持てる名前をつける（病院の患者分類、動物の名前など）
- **タイプは変わりうる**: 追加インタビューやデータで更新される前提
