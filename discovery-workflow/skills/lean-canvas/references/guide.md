# リーンキャンバス ガイド

## このガイドについて

リーンキャンバス（Lean Canvas）の書き方・使い方を解説する。テンプレートは [template.md](template.md) を使用。

## リーンキャンバスとは

プロダクトと市場の適合（Product-Market Fit）を1枚で俯瞰するためのフレームワーク。**左側にプロダクト、右側に市場**の情報を配置し、整合性を確認する。

検討した結果を1枚にまとめ、俯瞰して全体を意識しながら検討できる。**決まったことだけではなく、まだ決まっていないことも可視化していく**とよい。

```
┌──────────────┬──────────────┬──────────────┬──────────────┬──────────────┐
│ 課題         │ 解決策       │ 独自の       │ 圧倒的な     │ 顧客         │
│ Problem      │ Solution     │ 価値提案     │ 優位性       │ セグメント   │
│              │              │ UVP          │ Unfair       │ Customer     │
│              │              │              │ Advantage    │ Segments     │
│              │              ├──────────────┤              │              │
│              │              │ハイレベル    │              │              │
│              │              │コンセプト    │              │              │
├──────────────┼──────────────┤              ├──────────────┤              │
│ 既存の       │ 主要指標     │              │ チャネル     │              │
│ 代替品       │ Key Metrics  │              │ Channels     ├──────────────┤
│ Existing     │              │              │              │ アーリー     │
│ Alternatives │              │              │              │ アダプター   │
├──────────────┴──────────────┴──────────────┴──────────────┴──────────────┤
│ コスト構造 Cost Structure                                                 │
├───────────────────────────────────────────────────────────────────────────┤
│ 収益の流れ Revenue Streams                                                │
└───────────────────────────────────────────────────────────────────────────┘
```

## ディスカバリーワークフローにおける位置づけ

リーンキャンバスは各フェーズの成果を統合する「ハブ」として機能する。

```
Core定義 ──→ ミッション・ビジョン
  ↕ F&R         ↓ UVP・ハイレベルコンセプトへ
Why定義
  ├─ ユーザー側: VPC → インタビュー → KJ法
  │    ↓ カスタマーセグメント・課題・既存代替品へ
  ├─ プロダクト側: PEST → SWOT → STP → 競合分析
  │    ↓ 圧倒的な優位性へ
  ↕ F&R
What定義
  ├─ ソリューション・チャネル・収益・コスト・主要指標へ
  ↕ F&R
       ↓
  【リーンキャンバス】◀ 全層の検討結果を1枚に統合
```

## 4階層との対応

| 4階層 | 対応するリーンキャンバス項目 |
|:------|:---------------------------|
| **Core** | 独自の価値提案（UVP）、ハイレベルコンセプト |
| **Why** | カスタマーセグメント、アーリーアダプター、課題、既存の代替品、圧倒的な優位性 |
| **What** | ソリューション、主要指標、チャネル、コスト構造、収益の流れ |

## 各要素の書き方

### 1. カスタマーセグメント

**問い**: 誰に提供するか？

- ターゲットとするユーザー層を具体的に記述
- **アーリーアダプター**（最初に使ってくれる人）も別途記載
- 可能であれば軸を定義してセグメントを分類する（例: 横軸「課題感」× 縦軸「ニーズ顕在度」の4象限）

**チェックポイント**:
- [ ] 具体的なペルソナがイメージできるか？
- [ ] セグメントが広すぎないか？

### 2. 課題

**問い**: その顧客はどんな課題を抱えているか？

- 顧客が感じている**ペイン（痛み）**を3つ程度リストアップ
- **既存の代替品**（現在の解決方法）も記載
- 各課題にはエビデンス（インタビュー結果、データ等）を付記

**チェックポイント**:
- [ ] 顧客が「お金を払ってでも解決したい」と思う課題か？
- [ ] 既存の代替品と比較して勝てる見込みがあるか？

### 3. 独自の価値提案（UVP）

**問い**: なぜ我々が解決すべきか？独自の価値は？

- **1文で表現**できるシンプルなメッセージ
- **ハイレベルコンセプト**（〇〇の△△版）も有効

**チェックポイント**:
- [ ] 顧客の課題を解決できているか？
- [ ] 競合との差別化ポイントが明確か？

### 4. ソリューション

**問い**: 課題をどう解決するか？

- 課題に対応する**具体的な機能・仕組み**を記載
- 最初はMVP（実用最小限）で十分

**チェックポイント**:
- [ ] 課題と解決策が1対1で対応しているか？
- [ ] 実現可能な解決策か？

### 5. チャネル

**問い**: どうやって届けるか？

- 顧客に**認知してもらう方法**
- プロダクトを**届ける方法**

**チェックポイント**:
- [ ] ターゲット顧客にリーチできるチャネルか？
- [ ] コストに見合うか？

### 6. 収益の流れ

**問い**: どうやって収益を得るか？

- 収益モデル（サブスク、広告、手数料など）
- 具体的な**価格設定**
- 顧客の**支払い意思額（WTP）**の根拠

**チェックポイント**:
- [ ] 顧客がその価格を払う意思があるか？
- [ ] 収益モデルが持続可能か？

### 7. コスト構造

**問い**: 何にコストがかかるか？

- **固定費**: 人件費、インフラ費用など
- **変動費**: マーケティング費用など
- **初期投資**: 開発費用など

**チェックポイント**:
- [ ] 収益でコストをカバーできるか？
- [ ] スケールしたときのコスト構造は？

### 8. 主要指標

**問い**: 成功を測る指標は何か？

- **North Star Metric（NSM）**: プロダクトの成功を測る最重要指標
- **KPI**: NSMを達成するための先行指標

**チェックポイント**:
- [ ] 指標の改善がユーザー体験の向上とリンクしているか？
- [ ] 計測可能な指標か？

### 9. 圧倒的な優位性

**問い**: 真似できない強みは何か？

- 競合が**簡単に真似できない**もの
- 最初は「？？？」でもOK（後から見つかることも多い）
- 例: 独自データ、ネットワーク効果、専門チーム、既存顧客基盤

**チェックポイント**:
- [ ] 本当に真似されにくいか？
- [ ] 時間とともに強化されるか？

## Fit & Refine（項目間の整合性確認）

ただ枠を埋めるのではなく**項目間の整合性が取れているか**を意識する。

```
課題 ←────→ ソリューション      課題と解決策が1対1で対応しているか？
  ↕                                ↕
既存代替品                    主要指標       既存代替品と比較して勝てる指標か？
  ↕                                ↕
カスタマーセグメント ←→ チャネル    ターゲットにリーチできるチャネルか？
        ↕
   独自の価値提案（中心）           全ての要素がUVPと矛盾していないか？
        ↕
   コスト構造 ←→ 収益の流れ       ビジネスとして成立するか？
```

**Refine判断の3パターン**:
1. **整合する**: そのまま採用し次のステップへ
2. **整合しない**: どちらかの要素を修正、またはスコープ外と判断
3. **上位層のRefineが必要**: Core（ビジョン）やWhy（課題定義）に立ち戻って再検討

## 記入順序

1. **顧客セグメント & 課題** - 常に出発点。ここを間違えると他が全て崩れる
2. **独自の価値提案** - 課題に対する自社の答え
3. **ソリューション** - 具体的な解決手段
4. **チャネル** - 届け方
5. **収益の流れ & コスト構造** - ビジネスの成立性
6. **主要指標** - 成功の定義
7. **圧倒的な優位性** - 最後でOK

> ただし「正しい順序」はない。最初のキャンバスは自然に思いついた順序で書けばよい。目標は完璧ではなく、アイデアの**スナップショットを素早く取る**こと。v1は**15分以内**で書き上げる。

## 検証の優先順位

1. **Desirability（望ましさ）**: 顧客が本当に欲しいか？
2. **Viability（実現可能性）**: ビジネスとして成立するか？
3. **Feasibility（実行可能性）**: 我々が作れるか？

| 要素 | 検証方法 |
|------|----------|
| 顧客セグメント | ユーザーインタビュー |
| 課題 | ユーザーインタビュー、VPC作成 |
| 価値提案 | ユーザーインタビュー |
| 解決策 | プロトタイプテスト |
| 収益の流れ | WTP調査 |

## バージョニング

リーンキャンバスは検証のたびに更新する。大きな変更時はバージョンを分けて管理する。

| バージョン | タイミング | 主な変更 |
|-----------|-----------|---------|
| v1 | ディスカバリー開始時 | 仮説ベースで全項目を記入 |
| v2 | VPC作成・仮説検証後 | 課題・セグメントの精緻化 |
| v3 | インタビュー検証後 | エビデンスに基づく更新 |
| v4 | ブランドコンセプト確定後 | UVP・優位性の確定 |

## 他フレームワークとのインプット・アウトプット関係

| リーンキャンバス項目 | インプット元 | 参照フレームワーク |
|-------------------|------------|------------------|
| カスタマーセグメント | VPC カスタマープロフィール | STP分析 |
| 課題 | VPC Pains | KJ法分析結果 |
| 既存の代替品 | 競合分析（Who-What-How） | ファイブフォース |
| UVP | ブランドコンセプト | Core ビジョン |
| 圧倒的な優位性 | SWOT（強み × 機会） | 競合分析 |
| ソリューション | VPC バリューマップ | インタビュー検証結果 |
| チャネル | STP ターゲット特性 | PEST（技術トレンド） |
| 主要指標 | NSM設計 | ロードマップ |
| 収益・コスト | ビジネスモデルキャンバス | 事業戦略 |
